# Packet and blind testing

## Summary

Reduce the learner load while preserving coverage and an honest test of the written rules.

^testing-summary

## A small player-facing pack

Use the existing ten-page starter packet as a **working pilot packet**. Only pages 2-5 are the main procedural rules; other pages are setup, profiles, individual crew sheets, host record and templates. Print the selected crew sheet per player, with one shared rules copy and one reference. Players do not need the research notes, full catalogue, simulation plan or raw data schema.

The profile table already contains weapon keyword rules in each row. Keep that principle: show the rule where the player uses the item. Explain tokens and the round loop before optional exceptions. Fixed mirrored crews remove list-building and unpriced-choice confounds; they do not prove every role or scenario balanced.

## Progressive coverage without overwhelming players

Start with a full basic objective battle. Add **one module or a small related bundle** per wave. Each supplemental sheet must include every changed profile, condition and procedure required for that module. Do not send a card saying use hacking without the terminal, Interact, range, failure and counterplay rules.

Late-stage tests must recombine modules and use the final full reference set. Simplifying every test forever would miss interaction and reference-load problems. A mechanic used zero times remains uncovered, whether its text was in the packet or not.

## Unguided protocol

- Use players who have not learned this packet from the designer. Repeat players can test balance but cannot supply fresh first-read evidence.
- Ask them to set up and play using the files, not a verbal walkthrough. Clarify logistical matters only; log rule teaching separately.
- Observe setup mistakes, time to first legal turn, searches, contradictory interpretations, pauses, abandoned choices and scoring/end-state resolution.
- Record which page was sought, what was expected, whether the answer was found, and whether it solved the problem.
- If rescued, classify the failed task and continue with the correct assisted label. Do not bury failures in a final fun score.

## Preflight before wider sharing

- [ ] Confirm all selected item/skill values against the current owning cards.
- [ ] Label the starter mission and fixed rosters as test fixtures.
- [ ] Print in black and white; check the calibration line and template diameters at 100%.
- [ ] Check every action a participant can legally choose has an answer in the pack.
- [ ] Test the file link from a non-owner account and a mobile device where possible.
- [ ] Include version, a brief change log, exact requested test, time expectation, required materials and feedback route.
- [ ] Complete one unguided pilot before a large public wave.

Historical warning about broad blind distribution too early: [The Conception of Viticulture: February 2012](https://stonemaiergames.wordpress.com/2012/08/29/the-conception-of-viticulture-february-2012/). This is a staged recommendation, not a ban on early public feedback.
