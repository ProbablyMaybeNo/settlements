# Review checklist

## Summary

Check data quality and competing explanations before presenting a rule-change recommendation.

^testing-summary

## Before the review

- [ ] Correct source version, packet hash and board/crew/scenario revisions recorded.
- [ ] Complete, stopped, assisted and unguided sessions identified accurately.
- [ ] Raw observations kept separate from interpretations and proposals.
- [ ] Duplicate reports merged without losing independent-group counts.
- [ ] Opportunities recorded for any claim based on non-use.
- [ ] Draws and missing values retained; no silently excluded inconvenient games.
- [ ] Player skill, side, initiative, mission role, terrain and learning effects considered.
- [ ] A strong unpriced item is not automatically called broken.
- [ ] An unexercised rule/profile is not called balanced or weak.
- [ ] Physical and virtual handling differences considered.
- [ ] Confidence and limitations accompany effect sizes.
- [ ] Proposed wording stays concise; test instrumentation stays out of the rulebook.
- [ ] Decision owner, affected files and retest are identified.

## Before closing a wave

Write: what we learned; what changed by approval; what did not change; what remains uncertain; the next question. Publish a short participant-facing update only through an explicitly authorised channel. No automatic posting or messaging is part of this workspace.
