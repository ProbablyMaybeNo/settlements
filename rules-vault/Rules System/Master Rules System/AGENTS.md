# Settlements Master Rules System

The live source is this project’s `Rule Cards/` and `Item Cards/` owners. Start with `Settlements/START HERE - Settlements Project.md`. The assembled master and four reading sections embed approved owners. No copied master text owns rules.

Only current approved DRAFTED-or-later rules are published in active navigation. DRAFTED means complete enough to test, not balanced or playtested. Unapproved proposals, superseded copies, deferred items and previous review work live outside the active project under `Archive/Settlements/2026-11-10 - Superseded rules and working drafts/`. Do not reactivate them from their old status alone.

Procedure text belongs to Rule Cards; profiles belong to Item Cards. Catalogue tables are generated from item Rule text by the workspace plugin. Edit owners and refresh tables. Preserve IDs, valid anchors, feedback/provenance, unknown metadata and semantic dates. Housekeeping does not advance dates.

Keep Section → Mechanic → Rule organization, the workspace Base, item library Base and parent canvas with `^parent-summary` blocks. Do not create competing static inventories. Current chapter order is foundations → gameplay → setup → approved persistent play.

Latest explicit user decisions override older Pages, source snapshots and memories. Never adopt a recommendation or test variant silently. Existing simulation results use older contracts and do not validate the current rules.

Edit the live vault first, then run `scripts/sync-rules.ps1` to update the one-way repository mirror. Never edit `rules-vault/` directly.
