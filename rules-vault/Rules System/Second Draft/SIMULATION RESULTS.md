
## Simulation Reports

### Please use the following format to record your simulation reports.

*Simulation title + Number*
- Each simulation run should be given a title and a number in sequential order based on the last simulation. Titles should provide a very brief overview of what was simulated in the report.
  
  EXAMPLE: *Full Skill Simulation #4

*Overview list of what was tested*

- Don't go into too much detail just provide enough so that the reader knows what they are looking at and can ask questions about for more detail. 
  
*Rules Mechanic/System Status*

- On the overview list each mechanic or system tested should have a status next to it's name which can tell the reader at a glance if the simulations for that mechanic PASSED / FAILED / PENDING / BLOCKED etc. Passed means the mechanic that was simulated works will within the rules system and doesn't need adjusting. FAILED is the mechanic does not work in the system and needs to be removed or completely re-worked. PENDING tells the reader that the mechanic should work within the system but might jsust need a small adjustment, clarification, or change. BLOCKED this should be used if the simulation cannot test the mechanic for whatever reason or if it needs my input or whatever. 
  
*Brief Description*

- Each entry on the list should be followed directly by a very short description of the simulations findings regarding that specific test/mechanic/system explaining what the results was and why it received it's status specifically. 
  
*Report*

- Finally maybe at the top of each simulation run there should be a concise report outlining the findings of the simulation from a higher level perspective, what works, what doesn't, what needs more testing, to be removed, etc. No need for details as those will be in the ovberview list below but a straight forward, in laymens terms, report on the simul;ations would be great.
